# Use LangGraph for bounded Agentic RAG orchestration

Status: Accepted

Amended by [ADR-0008](0008-two-phase-agentic-evidence-recovery.md) for pre-generation evidence recovery, empty-pool handling, context selection, and same-context Answer review. The local implementation has migrated; conflicting decisions below describe historical behavior.

ADR-0001 kept the first Agentic RAG implementation framework-light until graph orchestration became useful; the hybrid retrieval, answer-generation, and answer-review transitions now justify LangGraph's explicit state graph. Use a reusable compiled `StateGraph` for Agentic RAG while retaining Pydantic action validation, one validation retry for malformed controller output, read-only note search, answers restricted to evidence retrieved in the current query, and abstention when evidence is insufficient.

Use the shared original-query Search and ranking baseline. If the initial ranked candidate pool is non-empty, send the first Generation top-k directly to Answer generation; do not run a controller evidence-sufficiency gate before it. If the initial candidate pool is empty, return a deterministic `no_retrieval_results` outcome without a controller or Answer call. Empty Retrieval is not evidence of query ambiguity or corpus absence. Buffer every Agentic candidate until the controller reviews it against the exact ordered Generation context and accepts it.

After generation, the controller may accept, request a focused same-evidence revision, expand from the current candidate pool, request another adaptive Retrieval search, clarify a genuinely ambiguous query, or abstain. Clarification is for query ambiguity, not missing or irrelevant evidence. A later Search carries a validated rewritten query, filtering thresholds, and replace-or-extend evidence mode back into Retrieval. It may execute only while both a Search attempt and a later Answer attempt remain. Reopening Retrieval does not reset either budget; controller calls, validation retries, and rejected pre-execution actions consume neither budget.

Use separate configurable total-attempt budgets for Search and Answer generation as defined by ADR-0007. Exhausted Answer review returns the deterministic `answer_attempts_exhausted` outcome without exposing the rejected candidate. An action that requests work outside a remaining budget receives the same single validation retry as other invalid controller output and then terminates as `controller_failure` if it remains invalid. Preserve a sanitized controller failure category and safe workflow trace, but do not persist raw prompts or model outputs. Ragas judges remain evaluation-only and do not participate in runtime review or routing.

Invoke the graph with fresh per-query state and no checkpointer or thread persistence; bounded Retrieval reopening remains read-only and isolated to that state. Do not add external tracing or monitoring integrations. Classic RAG remains the default workflow and retains its existing retrieval, empty-result, and streaming behavior.
