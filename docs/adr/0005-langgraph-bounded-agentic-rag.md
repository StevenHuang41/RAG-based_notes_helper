# Use LangGraph for bounded Agentic RAG orchestration

Status: Accepted

ADR-0001 kept the first Agentic RAG implementation framework-light until graph orchestration became useful; the hybrid retrieval, evidence-selection, answer-generation, and answer-review transitions now justify LangGraph's explicit state graph. Use a reusable compiled `StateGraph` for Agentic RAG while retaining Pydantic action validation, one validation retry for malformed controller output, read-only note search, answers restricted to evidence retrieved in the current query, and abstention when evidence is insufficient.

Bound the workflow with separate budgets: at most three Search attempts including the original-query search, and at most three Answer attempts including the first candidate generation. After each candidate generation, the controller reviews the answer against the selected evidence and either accepts it, requests a focused revision, requests another adaptive Retrieval search, asks the user to clarify, or abstains. A review-requested search carries a validated rewritten query, filtering thresholds, and replace-or-extend evidence mode back into Retrieval. It may execute only while both a Search attempt and a later Answer attempt remain. Reopening Retrieval does not reset either budget, and controller calls, validation retries, and rejected pre-execution actions consume neither budget.

If the third candidate still requires revision, return the deterministic `answer_attempts_exhausted` outcome without exposing the rejected candidate. An action that requests work outside the remaining budget receives the same single validation retry as other invalid controller output and then terminates as `controller_failure` if it remains invalid. Ragas judges remain evaluation-only and do not participate in runtime review or routing.

Agentic answers are buffered until review completes, because streaming a candidate before acceptance would expose text that the workflow may reject. Every accepted generated answer must pass review against its currently selected evidence. Invoke the graph with fresh per-query state and no checkpointer or thread persistence; bounded Retrieval reopening remains read-only and isolated to that state. Do not add external tracing or monitoring integrations. Classic RAG remains the default workflow and retains its existing streaming behavior.
