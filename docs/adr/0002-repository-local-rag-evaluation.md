# Keep the notes benchmark local to the repository

The notes QA benchmark will use synthetic, reviewed note fixtures under `tests/fixtures/` and will never read user notes from `data/` or a user's persistent index snapshot under `storage/`. `--eval` is the only evaluation command and is a source-checkout development workflow because test fixtures and Ragas are not part of the installed runtime package. Each run writes its log, per-case results, token usage, and summary to a timestamped directory under the repository-root `eval/`, with generated runs ignored by Git and benchmark fixtures kept under version control. The Ragas judge runs in a separate Python process to isolate its ML/OpenMP runtime from FAISS and avoid native runtime conflicts observed on macOS.

The former user-index smoke command is removed rather than renamed. A FAISS index and chunk metadata are the corpus used by the application under test, not a reviewed evaluation dataset: they cannot supply stable questions, reference answers, expected evidence, or answerability labels. Reference-free Ragas diagnostics still require a prepared question set and the RAG execution output; they do not make an arbitrary user snapshot into a regression benchmark.
